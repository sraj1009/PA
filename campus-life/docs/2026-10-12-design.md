# 校园生活小程序 (Campus Life) — Design

Date: 2026-10-12 · Status: built and locally verified 2026-10-12 (see `../README.md` for measured output; DevTools-only items still open) · Owner: BEE
Location: `PA/campus-life/` (self-contained; BEE's own repo, CI and 767-test suite stay untouched)

## 1. What is being built

A WeChat Mini Program with two modules, seven sub-features, and **no cloud dependency**:

- **社交互动** — 校园树洞, 匿名一对一聊天 (5-min timeout), 兴趣社群匹配, 心情雷达
- **本地生活工具** — 本地探索打卡, 时间管理智能规划, 周边好店聚合

Visual: youthful, cool-toned (blue/green/purple), simple and versatile, one shared token set.

## 3. The constraint that shapes the design

A phone cannot reach `http://localhost:11434`. Local Ollama is reachable **only** in the DevTools simulator with domain checking disabled. So "local AI agent" and "runs on a device" cannot both be true with a single implementation.

**Decision: one agent interface, two interchangeable backends, auto-selected at launch.** Nothing above the interface knows which is active.

```js
agent.chat(msg, ctx)      -> { text, mood }   // tree-hole reply, chat turn
agent.classify(text)      -> { mood, intensity }
agent.match(profile, pool)-> ranked[]
```

- `LlmAgent` — `wx.request` to Ollama `/api/chat`, `qwen2.5:3b` default, JSON-Schema for `classify`, persona in the system prompt.
- `OfflineAgent` — lexicon sentiment + the keyword/IDF matcher proven above. Deterministic, instant, zero network.
- `probe()` on launch, 1.5 s timeout → pick backend. A failed call mid-session falls back to `OfflineAgent` for that call rather than showing an error screen.
- `mode-badge` in the UI states 本地模型 / 离线模式. The user always knows which engine answered; the AI is never presented as a human.

## 4. Layout

```
campus-life/
  app.js app.json app.wxss project.config.json sitemap.json
  pages/{index,explore,planner,shops,treehole,chat,groups,radar}/
  components/{mode-badge,nav-card,tag,progress-ring,empty-state,tab-bar,chat-bubble,mood-axis,shop-card,checkin-item,task-row}
  core/        pure JS, zero wx APIs — store, schema, matcher, planner, checkin, shopfilter, moodscore, format
  agent/       index (probe+select), llm.js, offline.js, lexicon.js, prompts.js
  data/        seed.js — groups, shops, spots (marked as sample data)
  theme/       tokens.wxss — one source of colour/type/spacing truth
  tests/       jest + miniprogram-simulate
```

Pages use standard `Page()`. **Build step 1 validates a `Page`→`Component` shim in the jest setup** so real pages render under simulate; if the shim cannot faithfully reproduce page lifecycle, the documented fallback is thin pages plus `Component()` view components, keeping every screen live-tested either way.

## 5. Storage

One versioned key, `cl:v1`, written by a single owner (`core/store.js` — `load / save / mutate`); no page touches `wx.setStorageSync` directly.

```
{ version, profile, moods[], posts[], chats[], checkins[], plans[], shops[], settings{} }
```

Migration = version check + one `upgrade()` step. On quota error: prune oldest chat messages first, then oldest closed posts, then surface it. Anonymous ids are random local strings — never device-derived, so posts cannot be traced back.

## 6. Feature behaviour (what "works" means, per feature)

- **校园树洞** — write post → `classify` tags mood → feed newest-first, filter by mood. Local-only; visible label: 内容仅存于本机.
- **匿名一对一聊天** — countdown from a `setTimeout`; UI warns at 30 s remaining, and at 5 min of inactivity the session closes, the transcript archives to `chats[]`, and re-entry starts fresh. No cross-device pairing; partner is clearly labelled 模拟/AI.
- **兴趣社群匹配** — keyword/IDF/co-occurrence over local tags; ranked with an **explainable reason** per match, since embeddings failed.
- **心情雷达** — six fixed axes (学业、社交、作息、运动、情绪稳定、兴趣投入), each 0-100, aggregated from the user's own check-ins plus classified posts over a 7/30-day window. The axis formula is a pure function in `core/moodscore.js`. Every point traces to data the user entered; no fabricated campus-wide statistics.
- **本地探索打卡** — spot list, check-in with GPS where permitted, manual fallback, streak + coverage.
- **时间管理智能规划** — user's tasks + fixed commitments → ordered plan. Constraint solver in pure JS (deadline, priority, duration, available blocks) so it is unit-testable without the LLM; LLM only rewrites the plan into prose.
- **周边好店聚合** — seeded sample catalogue (labelled as such), category filter, distance sort, favourites, offline detail.

## 7. Error handling

Missing storage key → seed defaults. Empty state in every list. Offline mode announced, never silent. LLM timeout → per-call fallback. Quota → prune path above. Bad LLM JSON → retry once, then `OfflineAgent`.

## 8. Verification (no "done" without a run)

1. `npm test` green in `campus-life/` (unit + component/page render).
2. Every page render-tested: real WXML mounted, a real tap driven, DOM asserted.
3. Persistence test: write → remount → state restored.
4. **Live LLM run** against the user's real Ollama: one chat turn and one classification, with measured latency and the actual returned text quoted.
5. Matcher and planner proven with before/after numbers on the seeded data.
6. Honest gap report: what only DevTools can confirm (on-device navigation, real GPS, share cards, `wx.request` domain whitelist) is listed as unverified — not called complete.

## 9. Phasing

- **A — 本地生活工具 + shell**: tokens, store, tab bar, 探索打卡, 智能规划, 好店聚合, full test harness. No agent dependency.
- **B — 社交互动 + agent**: adapter + both backends, 树洞, 聊天, 社群匹配, 心情雷达.

Each phase ends with its own live run and a status report; approval to build B is re-checked once A is verified.

## 10. Open risks

- DevTools never run here → visual polish is code-verified, not eye-verified. Mitigation: install DevTools (needs a WeChat QR login, a credential step) or user runs `npm test` output plus one simulator pass.
- `Component()` shim fidelity for `Page()` lifecycle — resolved by build step 1.
- Chat is a simulation on-device, not a social network. Labelled as such everywhere.
